# 各入口究竟返回什么

| 入口 | 真正作用 | 是否得到下载Cookie |
|---|---|---|
| B站扫码登录 · 连接下载会话 | 申请平台二维码，轮询确认，校验并保存返回的会话 | 平台成功返回时是；本轮没有真机登录验收 |
| 导入自己的 Cookie 文件/请求头 | 解析所选平台域名凭据并加密保存 | 来自用户已有Cookie；非B站不伪造身份验证 |
| 抖音/快手/TikTok 开放平台身份授权 | 配置服务后按已批准权限确认公开身份 | 否，不等于网站浏览器Cookie |
| 打开 XX App · 仅启动 | 显式打开已安装的官方应用 | 否；没有授权回调，没有其他App私有文件访问 |

## 自己扫码自己

B站二维码页面允许截图。Android10+还可保存原始二维码PNG。保存后在官方App的扫一扫中尝试从相册选码并确认；返回镜流等待实际校验。某些平台/版本不支持从相册识别登录二维码时，使用另一台设备扫码；应用不能替代平台的确认步骤。

不要把码分享给别人或上传到聊天。图片可能进入相册云备份，建议登录完成后删除。二维码到期必须刷新，镜流关闭/被系统杀死后可能需要重新申请。

## 为什么没有“授权镜流获取Cookie”弹窗

此前只启动了官方App，这条入口从未集成通用的获取Cookie授权接口。Android应用沙盒不允许普通应用读取另一个App的私有Cookie。真正的SDK/OAuth需要应用登记、签名/客户端标识、作用域、回调，通常返回授权码/访问令牌，不是浏览器Cookie。

这版明确分开入口，没有新增其余六个平台的自动下载会话登录。只是想下载时不需要部署auth-bridge，它不是Cookie解析服务器。

对其他平台，使用自己的电脑浏览器完成官方网页登录，从已登录的对应平台请求中取得Cookie头，或主动导出自己的Netscape cookies.txt到本机导入。不要购买他人Cookie，不使用来源不明的抓取/上传工具，不从document.cookie假设能获得HttpOnly凭据。平台未返回的字段与格式会继续按未知/不可用处理。
